# Documentation boundary

The wiki is operational context for humans and agents, not marketing copy. Describe current
capability exactly and label unimplemented architecture as a growth pattern, reference, or future
possibility. Keep examples topic-agnostic.

Explain not only what a mechanism does, but the cognitive failure it prevents, the owner of the
behavior, whether the control is soft coaching or hard enforcement, and the evidence that validates
the claim. Documentation must not upgrade an interface convention into a security guarantee or a
deterministic test into live host acceptance.

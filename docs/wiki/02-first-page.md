# Create the First Page

The empty canvas is deliberate. By the time a user clones Origin, their agent may already have
several onboarding conversations describing their work. The agent should use that evidence rather
than asking the user to configure a generic template.

## A good first-page proposal

- Names the question each proposed page helps the user answer.
- Uses the user's established language.
- Starts with the fewest useful pages.
- Separates observed needs from agent suggestions.
- States what will remain easy to change.
- Requires user approval only for consequential choices, not routine code.

The agent may begin with one useful page and extend navigation afterward. It should avoid inventing
sample companies, projects, metrics, or deadlines merely to make the dashboard look populated.

## Stable page identity

Routes and visible titles may change. Give a cultivated page a stable internal identity so existing
feedback remains attached to the same conceptual surface. Origin 1.0 records the current route and
page label. A mature dashboard can add a stable page ID before page renaming becomes common.

## Completion

The first page is complete when it renders at an intentional route, communicates its purpose, works
at small and large screen sizes, and the agent records how it verified the result. Visual population
alone is not proof of usefulness.

# Grow the Harness

The model supplies general intelligence. The harness supplies persistent local context,
deterministic controls, tools, state, and learned operating methods. The CLI model remains
replaceable; the durable behavior belongs to the repository.

Begin with conversation. When a behavior repeats, record what the user is actually teaching. Make it
a durable plugin only when its objective and boundaries are clear enough to test.

## Maturation path

1. The user corrects or guides the agent in conversation.
2. The agent recognizes a repeated pattern.
3. The pattern becomes written context or a reusable procedure.
4. Evidence shows where probabilistic instruction is insufficient.
5. A deterministic hook or guard enforces the proven invariant.
6. Redundant prose is removed after the enforced behavior is trusted.

Do not turn every preference into a hook. Hooks are appropriate for stable events and invariants;
judgment and evolving taste normally remain in context.

## Ownership test

A new capability deserves a plugin when one sentence can name its coherent objective, state
ownership, inputs, outputs, exclusions, and completion proof. If two capabilities cannot change
independently, they may still belong together. If several systems need the same low-level state,
that state may need a separate shared owner.

Origin's delivery adapter is intentionally narrow. Other CLI variants can replace the command
adapter while preserving the feedback contract, lifecycle, state, and evidence requirements. A
future `.claude`, `.qwen`, or OpenCode edition should translate host integration rather than fork
the cognitive rules.
